
图床存储在R2存储桶中，提供免费的10GB容量，个人用户足够使用。配置了缓存规则，因此不需要担心刷读取次数问题。无需使用服务器，避免了运维成本。支持上传 JPG / PNG / GIF / WebP / BMP 格式的图片，并且支持从 Telegram 发送原图。
增加web管理界面，可进行图片删除，新增文件夹，删除文件夹，上传等操作。
### 特性
#### 1.支持web管理
#### 2.支持新增/删除文件夹
#### 3.支持从TG机器人自定义上传路径
#### 4.支持一键复制（直链 / Markdown / HTML / BBCode 四种格式）
#### 5.图片按上传时间倒序排列（最新图片在最前，按天分桶，跨页不乱序）
#### 6.超过500KB的 JPG/PNG/BMP 图片在上传前自动于浏览器端压缩为 WebP（GIF/WebP 除外；压缩失败自动回传原图，不会导致上传失败；同时按 EXIF 方向自动摆正）
#### 7.支持多格式上传（JPG/PNG/GIF/WebP/BMP，前后端一致）
#### 8.图库大图预览（Lightbox，支持键盘 ←/→ 切换、Esc 关闭）
#### 9.支持 Ctrl+V 粘贴截图直传、拖拽上传、多文件并发上传（3 路）与单文件进度条、失败单文件重试
#### 10.图片重命名 / 移动（R2 copy+delete，防覆盖冲突检测；注意旧直链会失效）
#### 11.存储用量统计（总文件数/总体积/各文件夹占用/近 7 日上传，缓存 1 小时，写操作自动刷新）
#### 12.图库搜索过滤 + 排序切换（时间/名称）+ 网格/列表双视图（记忆偏好）
#### 13.移动端适配 + 暗色友好的响应式布局
#### 14.安全加固：KV 服务端会话（可登出吊销、改密全端失效）、登录限速、Webhook 防伪造校验、路径规范化防注入
#### 15.回收站：删除默认进回收站（保留原路径），可恢复 / 彻底删除 / 一键清空；可选 Cron Trigger 自动清理 30 天前的回收站对象

### 步骤指南

#### 第一步：获取 Telegram 机器人 Token 和用户 ChatID
- 参考链接：[获取 Telegram 机器人 Token 和 Chat ID](https://blog.xiny.cc/archives/mTaUz0TW)

#### 第二步：创建 R2 存储桶
1. 访问 [Cloudflare Dashboard](https://dash.cloudflare.com/)。
2. 创建一个 R2 存储桶，名字可以随意设置，完成后添加一个域名。

#### 第三步：创建 Cloudflare Worker
1. 在 Cloudflare 中创建一个空白 Worker，名字可以随意设置。

#### 第四步：创建 KV 数据库
1. 在 Cloudflare 左侧找到存储与数据库，创建一个KV数据库，名字可以随意设置。

#### 第五步：绑定 R2 存储桶与 KV
1. 在 Worker 的设置 → 绑定中，绑定 R2 存储桶。
2. 绑定 KV 数据库，变量名必须为 **INDEXES_KV**。
3. （推荐）在同一页面配置以下**环境变量**（敏感项选"加密"/Secret 类型）：

| 变量名 | 说明 | 类型 |
|---|---|---|
| `SECRET_KEY` | Web 后台访问密码 | Secret（加密） |
| `TELEGRAM_BOT_TOKEN` | Telegram Bot Token | Secret（加密） |
| `CHAT_ID` | 允许访问的聊天 ID，多个用英文逗号分隔 | 文本 |
| `BUCKET_NAME` | R2 存储桶绑定的变量名 | 文本 |
| `BASE_URL` | R2 访问域名（不带末尾斜杠） | 文本 |
| `WEBHOOK_SECRET` | 任意 32+ 位随机字符串，用于 webhook 防伪造校验 | Secret（加密） |

> 也支持旧方式：直接修改 `worker.js` 顶部的 `FALLBACK` 常量。但强烈建议使用环境变量，避免把 Token/密码提交到代码仓库。**若曾在源码中填写过真实 Token，请到 BotFather 重置。**

#### 第六步：编辑 Worker 代码
1. 复制完整的 Worker 代码粘贴进去并部署。

#### 第七步：设置 Webhook
1. 先访问 Web 后台登录（输入 `SECRET_KEY`）。
2. 登录后访问 `https://你的worker域名/setWebhook` 完成设置。
   （该页面需要登录后才能访问，且会自动带上 `WEBHOOK_SECRET` 防伪造校验。）

#### 第八步：开始使用
- 网页端：登录后即可上传（支持拖拽/粘贴）、管理图片与文件夹。
- Telegram 端：给机器人发送图片即可上传；`/modify blog` 切换上传目录；`/status` 查看当前目录。

### 升级须知（从旧版本升级）
1. **需要重新登录**：登录已改为 KV 服务端会话（支持登出吊销、改密全端失效），旧 Cookie 自动失效。KV 绑定（`INDEXES_KV`）为必需项。
2. **建议配置环境变量**：`SECRET_KEY`、`TELEGRAM_BOT_TOKEN` 迁移到 Secrets 后更安全（旧常量方式仍兼容）。
3. **需要重新执行 /setWebhook**：登录后访问一次 `/setWebhook`，让 Telegram 带上防伪造密钥。
4. **>500KB 自动压缩改为浏览器端执行**：上传前在浏览器压缩为 WebP（更可靠、不占 Worker CPU），压缩失败会自动回传原图，不再导致上传报错。
5. **图库分页改为按天分桶**：彻底修复旧版"超过 20 张后顺序错乱"的问题；图库顺序全局最新在前。
6. **重命名/移动的说明**：R2 无原生 rename，采用 copy+delete 实现，旧直链将失效（CDN 缓存最长一年内仍可能命中旧内容）。

### 与老项目无损切换清单

新代码与老项目（同一仓库旧版 worker.js）**数据层完全兼容**，可随时切换、也可随时回滚：

| 项目 | 兼容性 | 说明 |
|---|---|---|
| R2 存量图片 | ✅ 完全兼容 | key 格式（`YYYYMMDD_xxx.ext`）与老项目一致；老图可正常列出、排序、预览、直链不变 |
| 图片直链 | ✅ 完全兼容 | URL 结构不变，已发布的文章外链与 CDN 缓存不受影响 |
| KV 老数据 | ✅ 完全兼容 | TG 端上传目录仍按聊天 ID 存储，切换后 `/status` 显示的目录不丢 |
| 环境变量 | ✅ 双向兼容 | 优先读环境变量/Secrets，未配置时回退源码 `FALLBACK` 常量，两种配置方式都可用 |
| 登录会话 | ⚠️ 需重新登录 | 旧 Cookie 自动失效，用 `SECRET_KEY` 重新登录一次即可（1 次点击） |
| Telegram 机器人 | ✅ 自愈 | 配置了 `WEBHOOK_SECRET` 但未重跑 `/setWebhook` 时，机器人收到第一条消息会自动重新注册 webhook（1 小时节流），无需手动干预；也可登录后手动访问 `/setWebhook` 立即生效 |
| 删除行为 | ⚠️ 更安全 | 删除默认进回收站（可恢复），不再直接永久删除；彻底删除需二次确认 |

**推荐切换步骤**：
1. 备份当前 Worker 代码（Dashboard 里复制一份存档，方便回滚）。
2. 确认 KV 绑定 `INDEXES_KV` 存在（老项目本来就要绑）。
3. 粘贴新 `worker.js` 并部署。
4. 用 `SECRET_KEY` 重新登录。
5. （推荐）登录后访问一次 `/setWebhook`；不做也行，机器人会在下一条消息时自愈。
6. 完成。存量图片、直链、TG 目录设置全部保持原样。
